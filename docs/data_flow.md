# Data Flow Diagram (DFD)

## 1. Overview

This document describes the data flow within the Gitleaks Python Scanner, illustrating how data is processed and transformed as it moves through the system. The Data Flow Diagrams (DFDs) are represented using Mermaid syntax.

## 2. Context Diagram (Level 0 DFD)

```mermaid
graph TD
    A[User] -->|Provides target_projects.csv| B(Gitleaks Python Scanner)
    B -->|Generates Reports| C[Reports (HTML, Excel, CSV)]
    B -->|Interacts with| D[GitLab/Git Repository]
    B -->|Uses| E[Docker (Gitleaks)]
```

## 4. Data Stores

*   **`target_projects.csv`**: Input file containing details of Git repositories to be scanned.
*   **`Reports/json-reports/`**: Stores the raw JSON output generated by Gitleaks for each scan.
*   **`Reports/gitleaks-reports/`**: Stores the generated HTML and Excel reports.
*   **`Reports/gitleaks_summary.csv`**: Logs high-level summary information for each successful scan.
*   **`Reports/gitleaks_failures.csv`**: Logs details of any failed repository clones or Gitleaks scans.
*   **`tmp/`**: Temporary directory used to clone Git repositories during the scanning process. Contents are securely deleted after each scan.
*   **`template/report_template.xlsx`**: Excel template used for generating structured Excel reports.

## 5. External Entities

*   **User**: Provides the input `target_projects.csv` and initiates the scanning process.
*   **GitLab/Git Repository**: The source of the code to be scanned. The scanner interacts with these repositories to clone code.
*   **Docker (Gitleaks)**: An external tool that runs the Gitleaks secret scanning engine as a container. The scanner invokes Docker commands to perform the actual secret detection.
